Phase 0 · 土台

Emacsの世界観をつかむ

Vim と Emacs は「エディタ」の定義が違います。ここを誤解すると全部が遠回りになります。

目安 30分
レッスン 2

0-1. バッファ＝開いているもの全部

10分

Vim の「ファイルを開く」感覚に近いのがバッファですが、Emacs ではファイルでないもの（Magit画面、ヘルプ、ターミナル）も全部バッファです。「ウィンドウはバッファを覗く窓」と捉えると混乱が消えます。

DOOMSPC b b バッファ一覧から切替 ／ SPC b d 今のバッファを閉じる
VIM:ls と :b に相当。ただし Emacs のバッファはファイル以外も含む
NEOVIM:ls ／ Telescope なら SPC b b 相当（LazyVim）
やってみよう
  • 適当なファイルを3つ開いて SPC b b で行き来する
  • SPC h f で関数ヘルプを開き、それもバッファだと確認する

0-2. モードではなく「ステート」

10分

Evil の Normal / Insert / Visual は Vim とほぼ同じ。違いは、Emacs 本来のキー（C- 系）が Insert 中にも生きていることと、Emacs ステートという「素の Emacs」状態があること。

DOOMEsc Normalへ ／ Insert中 C-h ヘルプ、C-n/C-p 補完移動
VIMとの差C-c は Insert を抜けない（Doomでは設定で変更可）。まず Esc で覚える
やってみよう
  • Insert 中に C-a / C-e で行頭・行末へ動いてみる
  • ステータスライン（モードライン）で今のステート表示を確認する
Phase 1 · 生存

ファイル・バッファ・ウィンドウ

ここが回れば「とりあえず Doom で仕事ができる」状態になります。SPC の2文字目がカテゴリです： f=file, b=buffer, w=window, p=project。

目安 1時間
レッスン 3

1-1. ファイルを開く・保存する・最近のファイル

15分
DOOMSPC . / SPC f f ファイル検索 ／ SPC f r 最近開いたファイル ／ SPC f s 保存
NEOVIMLazyVim: SPC f f (Telescope find_files) ／ 素の Neovim: :e ファイル名
やってみよう
  • :w の代わりに SPC f s で1日保存してみる
  • 存在しないパスを SPC f f で入力すると新規ファイルになることを確認

1-2. ウィンドウ分割は Vim とほぼ同じ

10分
DOOMSPC w v 縦分割 ／ SPC w s 横分割 ／ SPC w d 閉じる ／ C-w h/j/k/l 移動（Vim互換あり）
VIM:vs / :sp / C-w 系はそのまま使えることが多い
やってみよう
  • 縦分割して左右で別ファイルを開き、C-w w で行き来する
  • SPC w m で今のウィンドウだけ最大化 → もう一度押して戻す

1-3. プロジェクトという単位

15分

Doom は Git リポジトリなどを自動で「プロジェクト」として認識します（Projectile）。SPC p 配下がプロジェクト操作の入口です。

DOOMSPC p p プロジェクト切替 ／ SPC p f プロジェクト内ファイル検索 ／ SPC p a プロジェクト追加
NEOVIMTelescope find_files が cwd 単位で近い感覚。プロジェクト切替はプラグイン依存
やってみよう
  • 自分のリポジトリを2つ登録して SPC p p で切り替える
Phase 2 · 編集

Vimの編集を「拡張」する

モーション・オペレータ・テキストオブジェクトは既に知っているはず。ここでは Doom / Evil が足したものだけを拾います。

目安 1〜2時間
レッスン 3

2-1. そのまま使えるもの（安心材料）

10分

ciw di" ys 系の基本、. リピート、マーク、マクロ q、レジスタ——大半は Evil が再現しています。まずは疑わず Vim のつもりで打ってみてください。

Vimと違う所： アンドゥはツリー構造です。u で戻り、C-r で進むのは同じですが、途中で編集すると分岐が残ります。またヤンクは Emacs の kill-ring と連動するため、p の挙動が微妙に違う場面があります。

2-2. コメントと整形は SPC c 系＋ gc

15分
DOOMgcc 行コメント切替 ／ gc＋モーション 範囲コメント ／ SPC c 配下に LSP・整形系
NEOVIM標準では gcc は Neovim 0.10+ で組込みあり。それ以前は Comment.nvim 等
やってみよう
  • Visual で数行選んで gc でまとめてコメント／解除する

2-3. 検索と置換：バッファ内 → プロジェクト全体

20分
DOOM/ バッファ内検索（Vim同様）／ SPC s s 候補一覧で絞る検索 ／ SPC s p プロジェクト全体を ripgrep 検索 ／ SPC s r 置換系
NEOVIM/ は同じ。全体検索は Telescope live_grep（LazyVim: SPC /）
やってみよう
  • SPC s p で自分のコードから関数名を全体検索し、結果からジャンプする
  • 検索結果バッファも「バッファ」として扱えることを確認する
Phase 3 · 移動と補完

コードを「読む」速度を上げる

定義ジャンプ、参照、ドキュメント表示。LSP が効いている言語では Vim 時代より一段速くなります。

目安 1時間
レッスン 2

3-1. gd / gr / K は共通言語

15分
DOOMgd 定義へ ／ gD 参照一覧 ／ K ドキュメント表示 ／ C-o 戻る（Vim同様のジャンプリスト感覚）
NEOVIMLSP 有効時 gd / gr / K がほぼ同じ役割
やってみよう
  • よく使う言語で gd → C-o の往復を5回繰り返す

3-2. 補完は Insert 中の C-n / C-p

15分

Doom の補完（Corfu / Company は設定依存）は Insert ステートでポップアップします。候補移動は C-n/C-p、確定は Enter や C-Enter 系（環境で差あり）。自分の環境で SPC h k を使って実際の割当を確認してください。

やってみよう
  • 補完候補を出した状態で SPC h ではなく、一度 Normal に戻ってから候補キーのヘルプを引く練習をする
Phase 4 · Emacsの強み

Magit と Org — ここが本丸

多くの Vim ユーザーが Doom に移る決め手がこの2つです。Vim 側に完全な対抗馬がない領域なので、優先して触ってください。

目安 2時間〜
レッスン 3

4-1. Magit：Gitをバッファで操作する

30分
DOOMSPC g g Magit status ／ 中では s stage、u unstage、c c commit、P p push、F p pull
NEOVIMNeogit が近い体験。LazyGit（外部TUI）を端末で開く運用も人気

Magit のキーは Vim とも素の Git とも違う独自体系ですが、画面に出るヒント（transient メニュー）を読みながら進める設計です。まず status → stage → commit → push の一本道だけ覚えれば実用になります。

やってみよう
  • テスト用リポジトリでファイルを変更 → SPC g g → s → c c でコミットまで完走する
  • hunk（差分の一部）だけ stage できることを試す ← これが Magit の真骨頂

4-2. Org mode 入門：メモとTODOを同じファイルに

30分
DOOMSPC n 配下が notes 系（環境設定に依存）／ Org バッファ内では見出し移動・TODO切替が Tab や SPC m 系のローカルリーダーに集まる

Org は「Markdown の先祖にして上位互換」のような存在で、見出し・リスト・TODO・表・コードブロックがプレーンテキストで書けます。Doom では org モジュールを有効化するのが前提です（Phase 6 の設定編参照）。

やってみよう
  • notes.org を作り、見出し3つ＋TODO 2つを書いて折りたたみ（Tab）を試す

4-3. ヘルプを使い倒す（自走力）

15分
DOOMSPC h f 関数を調べる ／ SPC h v 変数 ／ SPC h k キーの割当 ／ SPC h d Doom のドキュメント・FAQ系
NEOVIM:help 対象 ／ :map キー確認。思想は同じ「エディタ内蔵ドキュメント」

Emacs のヘルプはエディタの中に全部入っています。「ググる前に SPC h」が身につくと、学習速度が一段変わります。

Phase 5 · Neovim橋渡し

Neovimと行き来できるようになる

Doom と Neovim（特に LazyVim）は「ディストリビューション」という考え方自体がそっくりです。対応関係を押さえると二刀流が楽になります。

目安 1時間
レッスン 2

15分

5-2. Neovimで違うのは「Lua」と「:」の世界

DOOM対応物： doom doctor ／ doom sync ／ LSP はモジュール有効化＋各言語サーバ導入
やってみよう

Phase 6 · 育てる

自分の設定ファイルを持つ

Doom の設定は3ファイルだけ。役割分担さえ分かれば怖くありません。

目安 1時間〜
レッスン 1

6-1. init.el / config.el / packages.el の役割

30分

~/.config/doom/init.el は「どのモジュールを使うか」の選択、config.el は自分の設定本体、packages.el は追加パッケージの宣言。変えたらターミナルで doom sync、困ったら doom doctor。

DOOMSPC f P 自分の設定ファイルを開く（Doom の定番キー）／ SPC h r r 設定のリロード系（表記は環境で確認）
やってみよう
  • config.el に行番号表示やフォントなど、小さな設定を1つだけ足して doom sync なしで反映されるもの／必要なものの違いを体感する

⇄

考え方の切替 — Vim脳のまま引っかかる所

操作よりも先に、この4つの前提がずれるとずっと違和感が残ります。

DOOM / EMACS

「全部バッファ、全部テキスト」

Git画面もヘルプもファイルツリーもテキストのバッファなので、Vim のモーションで読めて、検索できて、コピーできます。UIを覚えるのではなく「バッファを読む」感覚に寄せるのがコツです。

NEOVIM

「エディタ＋プラグインで組む」

Neovim は素の状態が軽く、Telescope や LSP を自分（や LazyVim）で組む思想。Doom の「モジュールを選べば揃う」と対照的です。両方触ると、自分の好みがはっきりします。

Exコマンドは補助輪

Doom(Evil) でも : から :w :q :e は使えます。最初は頼ってよく、徐々に SPC 系に置き換えていくのが現実的です。無理に断たなくて大丈夫。

「終了しない」という選択肢

Emacs は起動しっぱなしでバッファを開閉する文化が強く、emacsclient で既存の Emacs にファイルを開かせる運用も定番です。Vim の「開いて閉じる」と両方知っておくと楽です。

Neovim 最初の1週間でやること

  • :Tutor ではなく、まず :checkhealth で環境を緑にする
  • Telescope の find_files / live_grep だけ先に体に入れる
  • LSP は Mason から1言語だけ入れて gd / K を試す
  • 設定は init.lua に少しずつ。いきなり大きな構成をコピペしない

Vim / gVim から来た人の注意点

  • .vimrc はそのままでは使わない。Neovim は init.lua か init.vim を読む
  • クリップボードは clipboard=unnamedplus 相当を設定しないと OS と共有されないことがある
  • ターミナル内 Neovim が主戦場。GUI は Neovide など別プロジェクト

設定ファイル — 最小の実例

コピーして終わりではなく、「どこに何を書くか」の見本として使ってください。ボタンを押すとそのままコピーできます。

Doom： ~/.config/doom/config.el に足す小さな設定例

config.el — 表示と手癖の微調整だけ
;; 行番号を相対表示にする（Vim の relativenumber 相当の感覚）
(setq display-line-numbers-type 'relative)

;; テーマは Doom 同梱のものから選ぶ例
(setq doom-theme 'doom-one)

;; 保存時に末尾の空白を消す、など小さな好みはここに少しずつ
;; 大きく変える前に SPC h v で変数名を確認する癖をつける

Doom： ターミナルで使うコマンド早見

shell — doom コマンド
doom sync      # packages.el / init.el の変更を反映
doom upgrade   # Doom 本体とパッケージを更新
doom doctor    # 環境診断（困ったらまずこれ）
doom env       # 環境変数まわりで困ったとき

Neovim： ~/.config/nvim/init.lua 最小構成

init.lua — 素の Neovim 用の最小例
-- ~/.config/nvim/init.lua
vim.g.mapleader = " "          -- リーダーを SPC に（Doom / LazyVim と揃える）
vim.opt.number = true
vim.opt.relativenumber = true
vim.opt.clipboard = "unnamedplus"
vim.opt.expandtab = true
vim.opt.shiftwidth = 2

-- ファイル検索などは Telescope 等を入れてから割り当てる
-- vim.keymap.set("n", "<leader>ff", "<cmd>Telescope find_files<cr>")
NixOS でのメモ： あなたの環境は NixOS が前提なので、Doom / Neovim ともに「通常の手順で入れたバイナリや言語サーバがそのまま動かない」場面があります。詰まったらまず doom doctor / :checkhealth の出力を見て、不足している外部コマンド（ripgrep、fd、node、言語サーバなど）を Nix 側で用意する、という順番で切り分けてください。
