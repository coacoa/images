SSH越しに +y（clipboard）が突然使えなくなった時の即復旧メモ

NixOS / OpenSSH / Vim・Neovim 向け・再発前提チェックリスト

症状

  • SSH先の Vim / Neovim / Emacs で "+y してもローカルに貼れない
  • 昨日まで出来ていたのに 突然死

原因（今回の結論）

原因 接続先 sshd が X11 Forwarding を禁止していた。

X11 forwarding request failed on channel 0
X11Forwarding no

👉 壊れたのではなく、設定どおり拒否されていた。

即チェック手順（再発時はここから）

  1. DISPLAY を確認 
    echo $DISPLAY
    • NG 空 → X11 未接続
    • OK localhost:10.0 → X11 OK
  2. ssh -X で入り直す 
    ssh -X user@host

    それでもダメなら sshd 側。

NixOS（接続先）での正解設定

services.openssh = {
  enable = true;
  settings = {
    X11Forwarding = true;
  };
};
sudo nixos-rebuild switch

xauth エラーが出た場合（初回あるある）

xauth: file ~/.Xauthority does not exist
touch ~/.Xauthority
chmod 600 ~/.Xauthority

→ 再接続

最終確認

echo $DISPLAY
"+yy

ローカルに貼れたら 復旧完了

なぜ「いつの間にか」起きる？

  • NixOS / OpenSSH 更新
  • sshd hardening
  • Wayland 前提化
  • 踏み台・別ホスト経由

👉 X11 はデフォルトで切られやすい

重要メモ（将来また折れる）

  • 不安定
  • sshd 設定依存
  • tmux / Wayland と相性悪い

安定解： OSC52 clipboard（X11 不要・sshd 不要）

合言葉

「壊れた」じゃない、「ssh の流儀が変わった」だけ

このメモ通りやれば 5分で復旧。
